## What this model is

L1은 Lunit과 Lunit Consortium이 만든 의료 도메인 특화 causal language model이다. `trillionlabs/Gravity-16B-A3B-Base`를 기반으로 하며, 임상 추론과 의사결정 지원을 주 용도로 설명한다.

- Architecture: GravityMoE, sparse mixture-of-experts with MLA
- Parameters: 16.24B total, 약 3B active per token
- Layers: 28
- Hidden size: 2,048
- Attention heads / KV heads: 16 / 16
- Experts: routed 64개 중 token당 top-8, shared 1개
- Context length: 32,768 tokens
- Vocabulary: 151,552
- Precision: bfloat16
- Tokenizer family: GLM-4.5
- Response behavior: 최종 답변 전 `<think>...</think>` 블록을 생성할 수 있는 thinking model

## Agent-facing operational notes

1. 이 저장소의 문서와 JSON은 모델을 **이해하기 위한 context**다. 모델 가중치를 Codex가 직접 읽거나 실행 가능하게 만드는 장치가 아니다.
2. 실제 추론에는 Hugging Face에서 별도로 모델을 받아 GPU 환경에서 Transformers, SGLang 또는 호환 serving stack으로 실행해야 한다.
3. 모델은 `trust_remote_code=True`를 요구한다. 프로덕션 사용 전 원격 Python 코드를 검토하고 revision을 고정한다.
4. 모델 카드의 예시는 reasoning overhead 때문에 `max_tokens` 또는 `max_new_tokens`를 2,048 이상으로 잡는다.
5. 의료 출력은 전문적 판단을 대체하지 않는다. 사실 오류, 누락, 오래된 정보 가능성을 전제로 검증한다.
6. 이 해커톤의 실제 대상인 `Lunit/L2-preview`와 L1은 서로 다른 모델이다. L1 문서를 L2의 retrieval/generation 계약으로 간주하지 않는다.
7. Evaluation 환경은 외부 네트워크가 차단되므로, 제출 container가 런타임에 이 Hugging Face 저장소를 내려받도록 설계하면 안 된다.

## Hackathon takeaways and warnings

이 문서는 L2의 동작 명세가 아니지만, 제출 harness의 배포·호출·검증 방식을 설계할 때 다음 운영 원칙을 참고할 수 있다.

### Directly useful guidance

- **Keep model weights out of the submission image.** L1 가중치는 약 32.5GB이므로 5분 이내 Docker image build와 격리된 evaluation 환경에 적합하지 않다. 제출 container가 Hugging Face에서 모델을 런타임 다운로드하도록 만들지 않는다.
- **Bound model and tool usage.** Thinking token과 반복 호출은 latency 및 token 사용량을 크게 늘릴 수 있다. Model 호출 횟수, retrieval turn, tool call, retry, timeout에 각각 명시적인 상한을 둔다.
- **Do not fill the context window by default.** 검색 결과는 관련도와 citation 가능성을 기준으로 제한하고, 같은 문서나 인접 chunk가 context를 독점하지 않도록 한다.
- **Validate hidden-reasoning markup defensively.** 실제 대상 모델의 출력에서 `<think>` 같은 내부 reasoning tag, 닫히지 않은 tag, tool-call markup과 일반 text의 혼합이 나타나는지 먼저 확인한다. 나타날 경우 사용자 응답에서 제거하거나 오류로 처리하되, L2가 L1과 동일하게 동작한다고 미리 가정하지 않는다.
- **Evaluate the model and harness together.** 공개 benchmark 수치는 목표 점수나 재현 결과로 간주하지 않는다. 동일한 decoding 조건과 평가 세트에서 baseline과 변경안을 비교하고, 설정과 실패 유형을 함께 기록한다.
- **Prefer evidence-aware answers over blanket refusal prevention.** 근거가 충분하면 구체적으로 답하고, 일부만 있으면 확인 가능한 내용과 한계를 분리하며, 근거가 없으면 추측하지 않는다. 중요한 임상 주장에는 실제 근거를 지원하는 citation을 연결한다.

### Conditional guidance for running L1 itself

다음 항목은 L1을 개발 baseline 또는 fallback model로 직접 실행할 때만 적용한다.

- Hugging Face revision을 고정하고 `trust_remote_code=True`로 실행되는 Python code를 사전에 검토한다.
- SGLang 및 custom GravityMoE 지원 버전의 호환성을 확인한다.
- GLM-4.5 tokenizer와 실제 chat template을 기준으로 token budget을 계산한다.
- bfloat16, GPU memory, cold-start time을 실제 배포 환경에서 검증한다.
- Thinking overhead를 포함해 output token budget을 정하되, 2,048이라는 값을 L2의 기본값으로 복사하지 않는다.

### Do not transfer these assumptions to L2

다음은 L1 전용 정보이므로 `Lunit/L2-preview`의 계약이나 기본 설정으로 사용하지 않는다.

- 32,768-token context length
- GLM-4.5 tokenizer 및 L1 chat template
- GravityMoE architecture와 expert routing 설정
- `<think>` block 생성 여부
- SGLang serving 및 `trust_remote_code=True` 요구사항
- L1 generation parameter 권장값
- 모델 카드의 MCQA 및 HealthBench 점수

L2의 prompt, tool schema, retrieval/generation 단계, context limit, 지원 parameter는 `../HACKATHON.md`, `../SUPPORT_PARAMETER.md`와 실제 endpoint 관찰 결과를 우선한다.

## Minimal inference references

Transformers:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "learning-unit/L1-16B-A3B"
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    device_map="auto",
    torch_dtype="auto",
    trust_remote_code=True,
)
```

SGLang is the model-card-recommended serving path. The current upstream instructions should be checked before installation because its custom GravityMoE support can change.

## Refresh policy

로컬 workspace의 `etc/scripts/update_l1_model_context.py`로 upstream 변경을 반영할 수 있다. 이 helper는 제출 Git 저장소에 포함하지 않는다. 갱신 후 다음 diff를 검토한다.

- `source.revision` and timestamps
- architecture/config changes
- chat template digest changes
- newly introduced remote-code files
- license or limitations changes
